# Rank feasible meals Task Specification

## Basic Information

- Task ID: T7
- Task name: Rank feasible meals
- Task type: Decide
- Task owner: Cookable workflow owner (student project team)

## 1. Task Description
Order only candidates marked feasible by T5 using a deterministic lexicographic comparison: greatest count of distinct normalized recipe ingredient names also present in the student's available-ingredient list; fewest distinct required ingredient names missing; shortest known cooking time; lowest known estimated cost. Compare in that precedence, sorting unknown time/cost after known values only when candidates tie on all earlier criteria. Preserve input order for exact ties. Do not infer ingredient quantities, alter feasibility, or claim an unknown comparison value.

## 2. Inputs

### Input 1

- Input name: Screened meal set
- Contents and format: Request ID and T5 `feasible_candidates` outcome with candidate IDs, normalized matched/missing ingredient names and counts, cooking time, estimated cost, evidence references, and explicit unknown markers.
- Source: T5: Screen meals against constraints.

- If a required input is missing or invalid, or T5 outcome is `unable_to_complete`: Do not invent comparison values or produce a misleading order. Record the issue and notify the Cookable workflow owner. T5 routes `no_feasible_candidates` directly to T6; T7 is invoked only when at least one feasible candidate exists.

## 3. Outputs

### Output 1

- Output name: Ranked feasible meal set
- Contents and format: Request ID and feasible candidates in deterministic order with rank, criterion values, evidence references, and unknown values preserved. An empty ranked set is not a successful recommendation.
- Next task or recipient: T8: Present meal options.
- Complete when: Every feasible candidate has a rank generated by the stated criterion precedence, with input order preserved for exact ties; do not produce this output for a no-feasible or unable-to-complete T5 outcome.

## 4. Planned Tools

### Tool 1

- Tool name: rank_feasible_meals
- Input: Screened meal set
- Output: Ranked feasible meal set
- Implementation Route: Deterministic in-memory sort using the fixed lexicographic criterion precedence; no model inference or external data lookup.
- Integration approach: Direct integration.
- Role in this task: Order only candidates marked feasible by T5. Unknown values sort after known values for the corresponding criterion and are never converted into estimated values.
- Task timeout: 5 seconds per request.
- Maximum retries: 1
- Retry only when: A transient execution failure is confirmed and no output was recorded. The operation is read-only and deterministic; if outcome is uncertain, check for an output associated with the request ID before retrying.
- On timeout, exhausted retries, or an error that cannot be retried: Record the ranking failure and do not send an unranked list as a ranked result; notify the Cookable workflow owner.
